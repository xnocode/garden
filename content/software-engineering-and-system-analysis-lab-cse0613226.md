## Lecture 02

A project has three main parts:

- **Time**
- **Cost**
- **Scope (Product)**

> [!tip] Before Selecting a Project
> Before selecting a project, we have to do a **feasibility study**. It helps us decide whether the project is possible or not. It also helps us understand the product and its requirements.

==Feasibility Study==

1. Market Feasibility
	- Check the software product market. 
	- Find out if a similar product already exists. 
	- If a similar product exists, we have to decide:
	    - What new features our product will have.
	    - How our product differs from theirs.
2. Technical Feasibility
	- Before selecting our project, we have to check the technology.
	- Check whether the required technology already exists.
	- Find out if similar technologies are used in other products.
	- Check the requirements needed to run the product.
3. Financial Feasibility
	- Check whether the project can be completed within the budget.
	- Estimate the development and maintenance costs.
	- Decide how much users will pay for updates or new features.
4. Operational Feasibility
	- Check whether the product will work well in real life.
	- Think about how users will use the system.
	- Consider the **Sociotechnical System**.
	  **Example:** Foodpanda
	- Think about both the rider and the customer.
    
5. Legal Feasibility
	- Check the Terms and Conditions.
	- Follow the country's laws and regulations.
	- Make sure the product does not break any legal rules.

==Project Proposal==

1. Project Title
2. Problem Statement
	- Explain the problem that we are trying to solve.
3. Objectives
	- State the goals of the project.
4. Existing System Analysis
	- SLR (Systematic Literature Review)
	- Find out what problems the existing systems cannot solve.
5. System Features and Functionality
	- List the main features and functions of the system.
6. System Requirements
	- List the software requirements.
	- List the hardware requirements (if needed).
	- Mention any other requirements needed to run the system.
7. SWOT Analysis
	- Strengths
	- Weaknesses
	- Opportunities
	- Threats
8. Project Scheduling
	- Create a timeline for the project.
	- Set weekly tasks and updates.
9. Risk Analysis
	- Likelihood
	- Consequences
10. Cost Analysis
11. Future Scope
12. Conclusion
13. References
	- Use the IEEE reference format.
	- Check the format from reliable sources.
